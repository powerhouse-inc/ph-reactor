# Console v2 — Implementation Plan

Spec: [`2026-09-13-console-v2-design.md`](../specs/2026-09-13-console-v2-design.md).
Execute top-down; each task commits on its own and is recorded in
`sdd/2026-09-13-console-v2/progress.md`. The backend lands before the UI so the
SPA can consume real endpoints.

## Task 1 — The doc-change feed carries the action delta
Extend `DocChange` with `action_kind`, `action_field`, `action_value`; populate
them from the applied action's payload in the `apply_action` notify path
(`store.rs`). Update the `DocSnapshot::from_change` call sites (they ignore the
new fields).
**Acceptance:** a unit test asserts that a `set` action `{field: status,
value: accepted}` produces a `DocChange` with `action_kind=set`,
`action_field=status`, `action_value=accepted`; a `create` and a `delete`
produce the right deltas.

## Task 2 — Processors as subscriptions
Add `ActionFilter` (+ `matches`), `Processor::filter()` (default = models only),
`ProcessorSpec` (serde), `Reaction` (Log/Run/Emit/CreateDoc), and
`ConfiguredProcessor` (implements `Processor`: filter from spec, `on_change`
performs the reaction, records a bounded fire history). Persist specs in
`processors.json`; the manager hot-reloads on change.
**Acceptance:** unit tests for `ActionFilter::matches` (each constraint
combination), `ProcessorSpec` round-trip, and a `ConfiguredProcessor` that fires
its `Run`/`Emit` reaction on a matching change and stays quiet otherwise.
Integration: setting an `invoice` `status` to `accepted` fires the reference
processor exactly once.

## Task 3 — The processor API
`GET/POST /api/processors`, `PUT/DELETE /api/processors/:name`,
`GET /api/processors/:name/fires` in `settings/mod.rs`; wire the manager to the
persisted specs in `daemon.rs`.
**Acceptance:** a test creates a processor via the API, edits it, and removes
it; the manager reflects the change (hot-reload).

## Task 4 — LLM type drafting + the model registry
`GET /api/models` (registered types), `POST /api/llm/draft-type` (calls the
OpenAI-compatible endpoint; clear error with no key),
`POST /api/models/register` (validate + register an `L1` model). Add
`invoice@1` to the realistic models (status lifecycle + reducers).
**Acceptance:** a test against a local stub LLM gets a draft definition;
registering it makes the type appear in `GET /api/models` and create a document.
The `invoice` reducers work (a unit test drives `draft→accepted→paid`).

## Task 5 — Folders and group documents
Documents carry an optional `folder` field. `GET /api/groups/:name/docs`
returns the group's documents grouped by owner and folder; `GET /api/docs`
gains `?owner=` / `?folder=`.
**Acceptance:** a test creates docs with folders for two members of a group and
asserts the group-docs endpoint groups them correctly.

## Task 6 — The console v2 UI
Rewrite `settings/console.html`: the v2 IA (sidebar = identity + groups +
System; group view → members' drives → folders → documents; document view; the
new-document flow with the LLM type creation; processors; System views) and the
polished design system (gradient accent, glass cards, Inter, chips,
micro-interactions, empty states).
**Acceptance:** the live browser smoke drives the whole flow end to end with no
console errors; screenshots captured.

## Task 7 — Verification, docs, evidence
`cargo build` + `clippy --all-targets -- -D warnings` + `fmt --check` clean;
full test suite green. Update the README (console-v2 section). Record the SDD
progress + evidence (test output, screenshots).

## Task 8 — Merge to main
Merge `feat/ui` → `main` (the full console-v2 + backend), verified by a clean
build + tests on the merge result.
